1. The Race Condition (Phase 2):

In the `race_condition.py` script, what exactly causes the final
weight to be less than the expected value? Explain the role of the OS
Scheduler in this error.

ANS: The final weight is less than the expected value because both
threads access and update the same shared variable at the same time.
The operation is not atomic. One thread may read the value, and then
the OS Scheduler switches to another thread before the first thread
writes the updated value. The second thread may then overwrite the
value written by the first thread. As a result, some updates are lost
and the actual value becomes less than the expected value.


2. Mutex vs. Semaphore (Phase 3):

- What is the specific job of the `mutex`?

ANS: The mutex protects the critical section of the shared buffer.
It allows only one thread at a time to access and modify the buffer
and the index variables.

- What is the specific job of the `empty` and `full` semaphores?
(Why can't we just use a Mutex for everything?)

ANS: The `empty` semaphore counts the number of empty slots in the
buffer. The `full` semaphore counts the number of items available in
the buffer. A mutex alone cannot control whether the buffer is full
or empty. The semaphores are needed to make the Producer wait when
the buffer is full and make the Consumer wait when the buffer is
empty.


3. Deadlock Awareness:

In the Producer function, we wrote:

empty.acquire()
mutex.acquire()

What would happen if we swapped these two lines? (mutex first, then
empty). Imagine the buffer is completely full. Explain the potential
OS problem.

ANS: If we acquire the mutex first and then wait for the empty
semaphore, the Producer can hold the mutex while waiting for an
empty slot. If the buffer is completely full, the Producer will
block while holding the mutex. The Consumer needs the same mutex to
remove an item from the buffer and release an empty slot. Therefore,
the Consumer cannot proceed, causing the Producer and Consumer to
wait for each other. This can result in a deadlock.
